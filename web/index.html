YOUR DATA / LOCAL ANALYSIS

Analyze service metrics

Import an AWS CloudWatch GetMetricData JSON export, an Azure Container Apps or GCP Cloud Run JSON export made by this project, or a long CSV with timestamp,service,metric,value columns. Minute-scale observations are preserved without inventing one-second readings. The original RCAEval CSV format still works. Files are analyzed locally and are not saved by the server.

Export real AWS ECS service metrics

With an AWS CLI profile that can read CloudWatch metrics, run this from the project folder. Replace the cluster, service names, onset, and region with yours; then import the generated JSON above.

.\.venv\Scripts\python.exe aws_ecs_export.py --cluster production --services checkout payments --onset 2026-09-29T14:00:00Z --region us-east-1

Queries CPU and memory for each ECS service at one-minute resolution over 30 minutes before and after onset. The export stays on your computer.

Export Azure Container Apps metrics

Sign in with Azure CLI and use a subscription where you can read Azure Monitor metrics. Replace the resource group and service names with your Container Apps, then import azure-containerapps-export.json.

.\.venv\Scripts\python.exe provider_export.py azure --subscription YOUR_SUBSCRIPTION_UUID --resource-group production --services checkout payments --onset 2026-09-29T14:00:00Z

Exports rolled-up CPU nanocores, working-set bytes, and request counts at one-minute intervals.

Export GCP Cloud Run metrics

Sign in with Google Cloud CLI and grant access to Cloud Monitoring for the project. Replace the project, region, and service names, then import gcp-cloudrun-export.json.

.\.venv\Scripts\python.exe provider_export.py gcp --project YOUR_PROJECT --region us-central1 --services checkout payments --onset 2026-09-29T14:00:00Z

Exports service-level CPU and memory utilization and request count in one-minute buckets. CPU and memory are the mean of revision-level medians, shown as percent.
